## 一、一句话说清这个作品

**它是一个"上传台账 → 自动体检 → 按确认过的规则清洗 → 算出 PUE / 绿电占比 / 碳排 → 生成七段式报告"的网页智能体。**
纯前端运行，零依赖，数据不出浏览器；老师点开网址就能用，不需要装任何东西。

它刻意**不是**"把表格丢给大模型让它总结"：所有数字由代码计算，模型只在**可选**的"改写措辞"环节出现。
原因见第三节的决策 1。

## 三、四个设计决策（为什么这样做）

### 决策 1：确定性计算交给代码，模型只负责叙述

- **做法**：体检、清洗、指标、报告数字全部由 `assets/engine.js` 计算；大模型只在"AI 增强版"里改写措辞，且提示词限定"不得改动任何数字"。
- **为什么**：
  1. 作业要求 R12 要求"根据测试情况优化"，只有结果可复现，才谈得上"优化"；
  2. 评审最怕"看起来像 AI 编的"。数字可复现，报告才可信；
  3. 模型直接读表格容易在单位、合计上出错，而这类错误在能效报告里是硬伤。
- **代价**：需要写规则引擎（约 700 行 JS），但换来"同一份数据跑两次结果完全一致"。

### 决策 2：只标记、不删除异常值

- **做法**：PUE 越界、绿电 > 总用电、总能耗 < IT 能耗，一律保留原值 + 打标记，并单独成表。
- **为什么**：异常往往是真实问题（设备故障、计量错误）。删掉它，报告会"变好看"，但把该发现的问题洗没了。
  报告第 5 节因此叫"异常清单（仅标记，不删除）"。
- **例外**：完全重复的行（归一化后完全相同）会被删，因为它是录入重复，不是现象。

### 决策 3：单位混用按"行"修正，不按"列"

- **做法**：同一列里若出现约 1000 倍的量级差（如大部分是 1300，少数是 1.3），判定为 MWh 混入 kWh，**只修正这些行**，并逐行记录。
- **为什么**：整列统一乘 1000 会把原本正确的行算错。行级修正 + 改动明细，是唯一能复核的做法。
- **风险与兜底**：规则基于量级差，若数据里本来就有"超大客户"，可能误判——所以每一条修正都写进"改动明细"，并在报告"口径与来源"里声明该假设。

### 决策 4：纯静态、零依赖、数据不出浏览器

- **做法**：不用框架、不引 CDN、不用后端；Excel 解析用自写的 `xlsx-lite.js`（ZIP + `DecompressionStream` + `DOMParser`）。
- **为什么**：
  1. 作业要求"教师浏览器打开即可体验"，静态站点最不容易翻车；
  2. 能耗数据可能敏感，"数据不上传"本身就是加分项；
  3. 没有构建步骤，部署 = 上传文件夹，改一个字都不用重新打包。
- **代价**：不支持旧版 `.xls`、不支持多工作表合并、超大文件（>12 MB）需先拆分——这些都写进了 README 的"常见问题"。

## 四、九个节点：做了什么、为什么、在哪

> 工作流图见 `工作流图.png`；页面顶部「工作流说明」里也有同一张图与同样的表。

### ① 接入 / 文件接收

- **做什么**：接收 `.csv` / `.xlsx`；CSV 先按 UTF-8 严格解码，失败则按 GBK 解码；限制 12 MB。
- **为什么**：台账最常见的三个坑是"换行符、合并表头、GBK 编码"。先解决"读得进"，后面才有意义。
- **在哪**：`app.js → readFile() / decodeBuffer()`

### ② 解析为二维表

- **做什么**：CSV 自己写解析器（处理引号、逗号、换行）；XLSX 用 `xlsx-lite.js` 解 ZIP → 解压 `sheet1.xml` → 读共享字符串 → 还原成"表头 + 行"；表头去重、空行剔除。
- **为什么**：后续所有规则都基于"表头 + 行"这一个结构；解析层做干净，规则层就不用到处判空。
- **在哪**：`engine.js → parseCSV()`、`xlsx-lite.js → read()`

### ③ 数据体检（确定性）

- **做什么**：逐列统计缺失率、类型、去重值；按"站点+日期+关键指标"找重复行；用 1000 倍量级差找单位混用；统计日期格式种类；校验 PUE 边界与"总能耗/IT 能耗"是否自洽；校验绿电 ≤ 总用电、总能耗 ≥ IT 能耗；最后算出 0–100 健康分（完整性 30 + 一致性 30 + 有效性 20 + 唯一性 20）。
- **为什么**：先诊断再动手。没有体检的"清洗"是拍脑袋，也说不清改了什么。
- **在哪**：`engine.js → audit()`

### ④ 生成清洗计划（规则 + 人工确认）

- **做什么**：把体检结果翻译成**可读的计划**：字段映射（`IT能耗(kWh)` → `IT 能耗`）、单位换算（哪几行 ×1000）、日期规范化、去重键、缺失填充策略、异常标记策略；每条都带"为什么"。
- **为什么**：
  1. 让用户能"确认"，而不是被模型悄悄改数据；
  2. 计划本身就是报告"系统设计与实现"一节最好的素材；
  3. 计划是 JSON 结构，和设计文档里的 `plan.json` 提示词 schema 完全对应，将来换成大模型生成也能直接复用。
- **在哪**：`engine.js → makePlan()`

### ⑤ 执行清洗（确定性）

- **做什么**：按计划逐条执行，产出：清洗后数据、改动明细（原表行号 + 站点 + 日期 + 标记）、清洗前后统计；可选跳过某一步（界面勾选）。
- **为什么**：确定性执行才能复现；改动明细让"清洗"这件事可被复核，也方便写进报告的"测试与优化"。
- **在哪**：`engine.js → execute()`

### ⑥ 指标计算（确定性）

- **做什么**：PUE 均值/区间/峰值月、绿电占比、碳排（用电量 × 排放因子）、电费与平均电价、月度序列（PUE / 能耗 / 碳排）。
- **为什么**：公式写死在代码里，避免模型口算；排放因子显式可改、来源写进报告。
- **口径**：PUE = 总能耗 ÷ IT 能耗；绿电占比 = 绿电电量 ÷ 总用电量；碳排 = 用电量(MWh) × 因子。越界 PUE 不参与均值统计，但仍出现在异常清单里。
- **在哪**：`engine.js → metrics()`

### ⑦ 可视化（纯 SVG）

- **做什么**：PUE 月度折线、月度总能耗柱状、绿电占比环图；无第三方图表库。
- **为什么**：一张趋势图比十行数字更容易看出问题；手写 SVG 体积小、可离线、打印不失真。
- **在哪**：`app.js → lineChart() / barChart() / donut()`

### ⑧ 报告拼装（七段固定结构）

- **做什么**：结论 → 数据质量（前后对比）→ 能效（PUE）→ 绿色化（绿电/碳排）→ 异常清单 → 三条改进建议 → 口径与来源（含免责声明）。
- **为什么**：固定结构保证每次输出一致；第 7 段强制交代来源与假设，直接对应作业 R17"涉及能耗、碳排放数据时应注明来源或计算假设"。
- **在哪**：`engine.js → buildReport()`

### ⑨ 输出与留痕

- **做什么**：下载清洗后 CSV（带"清洗标记"列）、下载 Markdown 报告、打印/存 PDF；页面上保留改动明细与异常清单。
- **为什么**：交付物要能被复核——数据从哪来、改了哪几行、结论基于什么。
- **在哪**：`app.js → cleanedCsv() / download() / printBtn`

## 六、清洗规则明细（每条都能在界面上看到）

| 规则 | 判定方式 | 处理 | 为什么这样定 |
| --- | --- | --- | --- |
| 字段映射 | 别名表匹配（含括号单位、大小写、空格归一） | 映射到 10 个语义字段 | 表头写法千奇百怪，硬编码列序会错位 |
| 缺失 | 空 / 空字符串 | 同站点同日均值 → 全体中位数，打 `缺失填充` | 优先用"同一天同一机房"的上下文，比全局均值更合理 |
| 重复 | 站点+日期+关键指标（取整后）完全相同 | 保留首条，其余删除 | 只删"归一化后完全相同"的，避免误删同日多条真实记录 |
| 同日多记录 | 同站点同日出现多条但值不同 | 保留，打 `同日多记录` | 可能是分时段计量，删除会丢信息 |
| 单位混用 | 同列出现约 1000 倍量级差（≥3 行且 ≥2%） | 对这些行 ×1000 或 ÷1000，打标记 | 按行修正才对；整列换算会算错正常行 |
| 日期 | 支持 Y-M-D / D/M/Y / YYYYMMDD / 中文年月日 / Excel 序列号 | 统一为 `YYYY-MM-DD` | 多格式会让趋势图把一个月拆成两个点 |
| PUE 越界 | PUE < 1.0 或 > 3.0 | 标记，不删；不计入均值 | 物理下限是 1.0，越界多半是计量或录入问题 |
| PUE 口径不一致 | 与"总能耗 ÷ IT 能耗"偏差 > 5% | 标记 `口径不一致` | 同一份表里两种口径并存时，必须提示 |
| 逻辑冲突 | 总能耗 < IT 能耗；绿电 > 总用电 | 标记，不删 | 这是硬逻辑错误，删了就看不见 |
| 站点名归并 | 去掉"机房/栋/座/楼/区"与符号后相同 | 归并到出现最多的写法，打 `站点名归一` | A栋 / A座 / A栋机房 是同一个机房，不归并会把一个月拆成三份 |

## 十、已知限制（写进报告"不足"一节正好）

1. 只读取第一个工作表；不支持多表合并（月度分表需先合并）。
2. 不支持旧版 `.xls`；不支持合并单元格（会提示表头异常）。
3. 单位修正是启发式（1000 倍量级差），极端数据可能需要人工复核。
4. 日期歧义（05/01/2025）按 M/D/Y 处理，已在计划里注明。
5. 不做负荷预测、不做投资回报测算——这些需要模型与参数，超出"数据清洗与分析"的范围。
6. 浏览器直连大模型接口可能被跨域拦截，此时用"复制提示词"走人工粘贴。
